# presets/ · 终端预设

> **这两份现在已内置。** 首启时终端会把它们各导一份进「终端设置 · 方案区」，
> 名字后面挂着「内置」标，点「应用」即生效 —— 不必再手动导入。
> 转换走的是与「导入预设」完全相同的一条路（`parseChatPreset`），
> 所以内置的那份与手动导入的那份逐字一致。删掉了不会再重播；
> 想找回来就清掉 `localStorage['zts-builtin-presets:v1']`，或用下面的方法重新导入。
> 以下是这两个文件本身的手动用法（分享给别人、或改过之后重新导入时用）。

这里的每一份 `.json` 都是一份**可直接导入的预设**（酒馆 ChatPreset 格式），
在「终端设置 · 方案区 → 导入预设」里选文件即可。导入后作为一份方案存下来，
再点「应用」才对下一次生成生效。

| 文件 | 内容 |
| --- | --- |
| `终末停滞-协议预设.json` | 主预设，28 条，分七组：**回执与框架**（回执协议 / 入戏与虚构框架 / 认知边界 / 称呼与专名）、**角色·不越界**（角色不标签化 / 反套话·不越权 / 不抢话 / 叙述视角）、**文风**（参照原著）、**主线·输出**（文本格式 / 篇幅 / 推进与衔接 / 反八股 / 文风·私密场面 / 文风·交战段落）、**角色短信**（发言格式 / 篇幅 / 节奏 / 边界）、**输出纪律·两通道通用**（模型适配通用 / 禁用词表 / 情绪不放大·活人感 / 不写旁注）、**模型适配**（Gemini / GLM / DeepSeek / Claude·GPT） |
| `终末停滞-文风参照原著-轻量化.json` | 轻量版，4 条：文风参照原著 / 反八股 / 文风·私密场面 / 文风·交战段落。不带协议、格式与短信约束，只改语感 |

**文风本来就在预设里** —— 主预设的「文风（参照原著）」是常驻条目，「文风（私密场面）」
「文风（交战段落）」是两条**场面档位**条目（没走到那一档就不生效，靠触发词或条件句兜住）。
轻量版那份只是给你一个「不想用整套约束、只想改语感」时的替代品 ——
名字里的「-轻量化」就是为这个加的：它和主预设里那条「文风（参照原著）」不是一回事，
别把它当成主预设的别名。

> 一次只能「应用」一份预设（套用即覆盖生效快照），所以两份是**二选一**，
> 不是叠加。要叠加就改主预设那一个文件。
>
> 两份里 identifier 相同的条目（`ts-style-canon` / `ts-no-cliche` / `ts-intim-depth` /
> `ts-style-battle`）**逐字一致** —— 同一件东西不该有两种说法：看起来一样、读起来不一样，
> 才知道改错了。改其中一份就同步改另一份。

## 适用范围（`scope`）

同一条指令压在两条通道上，必有一边是错的：「每回合 1000–2000 字」会把短信撑成长信，
「一到三句、不加星号动作」会把推演的正文拆散。所以每个条目都带一个**适用范围**：

| `scope` | 管谁 | 什么时候进提示词 |
| --- | --- | --- |
| 不写（缺省） | 两条通道 | 主线推演与角色短信都注入 |
| `"main"` | 只管主线推演 | 只在「剧情推进」通道注入 |
| `"sms"` | 只管角色短信 | 只在低语者日志（单聊 / 群聊 / 主动来信）注入 |

这是本终端给酒馆格式加的一个字段 —— **酒馆读不懂也不报错，导回去无碍**。
`scope` 是条目的属性，不是内容里的免责声明：不归本通道管的条目在 `buildPresetContext`
里就出局了，连通联日志的「进了哪几条」都不会算上它。

在「管理预设」里，左列副标题会标出「仅主线 / 仅短信」，编辑面板有「适用范围」下拉。

判断标准很简单：**这条要求是不是只在某一侧才成立？**
「段落之间空一行」只在长篇里成立 → `main`；「每次不超过六十字」只在聊天里成立 → `sms`；
「不用外来标签」「不写旁注」「专名照原文」两侧都成立 → 不写 `scope`。

## 为什么需要「回执协议」这一条

从酒馆搬来的预设（梦鲸思客、小猫之神 之类）会让模型把回执包进它自己那套标签里 ——
`<dream_body>`、`<dream_after_format>`、`<dream_history>`、`<thought_of_chain>`、
`<UpdateVariable>` …… 本终端只认自己的协议，那些标签名会漏进正文里。
协议条目的作用就是把输出拉回终端自己这一套：正文写散文（或用标签化回执时放进
`<maintext>`），指令走 `<vars>` 或 ```json 围栏，二选一，不混用。

> 即使不导入这份预设，终端也会在展示层把外来标签与代码块清掉
> （见 `src/lib/plot.ts` 的 `stripAlienTags` / `scrubDisplay`）——
> 预设是从源头少写，清洗是兜底。

## 模型适配写的是什么

模型适配拆成五条：**通用**一条，DeepSeek / Gemini / GLM / Claude·GPT 各一条。
每条都以「若你现在由 X 驱动」开头 —— 模型读到不符合自己的条件会跳过，不必手动切；
嫌占字数就在「管理预设」里把用不上的那几条关掉（眼睛图标），一条一两百字。

**出厂只开着 DeepSeek 那一条**（Gemini / GLM / Claude·GPT 三条默认关闭）——
这份预设是照着 DeepSeek 调的，别家的适配条目原样挂着只会各说各话。你换了别家模型，
在「管理预设」里把对应那条打开即可；要用的正是 DeepSeek，那什么都不用动。

写的是**输出习惯**层面的东西，都是各家里最常见的毛病：

- **通用**：推理只放 `<thinking>`，不写正文草稿、不反复考据；不用 `---` 分隔线、不起小标题、
  不结尾总结；并且把「不要 X」当成正面目标 —— 写具体动作、对白、细节。
- **Gemini**：正文不用 Markdown；不整段英文或中英夹杂；不写思考摘要与「让我想想」式前言；
  不在结尾反问操作员；长上下文里别只认最后一条；否定要求要翻成正向写法。
- **GLM**：不复述规则、不给正文起小标题；不用「首先/其次/最后」组织叙事；不复读上一回合的句子；
  不用生造怪词（肉刃、匝道 这类）；角色口癖与称呼保持不漂。
- **DeepSeek**：不必「先分析再回答」；思考里不反复考据、不写草稿；不用破折号；
  中文不掺英文连接词；不给结论加「总结一下」。
- **Claude / GPT**：不复述规则、不重述上一回合结尾、开头不说「好的/明白了」、正文不写成条目清单。

以上都不涉及绕过任何模型自身的安全判断。

## 触发词写法

条目里的 `injection_trigger` 沿用酒馆的习惯：以 `🔵` 开头 = 常驻；
其余是关键词，命中当前上下文才注入（本终端按字面子串匹配，中文关键词照写即可）。

「文风（交战段落）」的触发词是 `交战 / 作战 / 开打 / 交手 / 开战 / 异端 / 残渣` ——
扫描的是**最近十轮对话加上操作员这一句**，不是全文。写「魔王」不算：那是个人，
委员会开会也会提他；触发词收的是**动作**，不是名词。

## 角色短信那四条

短信通道自己有一套写在代码里的硬规则（第一人称、一到三句、不用 Markdown 加星号），
那套**不随预设变** —— 预设这四条补的是它没覆盖的维度，不重述它已经说过的话：

- **发言格式**：只写真的会发出去的那些字 —— 不加旁白、不写环境、不写「（停顿）」、
  不用引号把整句括起来（加引号就成了剧本，不是聊天）。
- **篇幅**：一到两句，整轮撑死三条，通常不超过六十字；**有下限** ——「嗯」「好」也算完整一条。
  别每条都写满，满格回复像客服。
- **节奏**：允许寒暄、废话、答非所问、隔很久才回。不用每条都推进剧情。
- **边界**：看不到的东西不要说；不做内心独白式长段抒情；只回对方真的发过来的东西。

这四条与主线的「篇幅 1000–2000 字」「段落之间空一行」是**互斥**的，靠 `scope` 分开 ——
它们不会同时出现在同一份提示词里。

## 预填充（assistant_prefill）

预设里的 `assistant_prefill` 会被导入并随「套用」落进生效快照：**每次生成先替模型摆上这个开头**，
它顺着那句往下写，正文最终 = 预填 + 续写，预填那一截也会先上屏。

- 只在**主线剧情**通道生效（角色短信是「一到三句」的聊天，塞一段叙事开头只会走样）。
- 导入时顺带读的是顶层 `assistant_prefill`，也认采样器层的同名字段；空白即关闭。
- 两份预设都留空 —— 它不是必填项。想用就填，例如给一段固定的开场语，或让它先起个引号。
  字数上限 400，超出即截断。

## 采样器

两份预设都带了温度 / top_p / 输出预算等采样器设置，导入时会一并套到双通道上；
**没有**写模型名 —— 导入时会沿用你当前通道里已填好的模型。
