## 方法与尺子（先把「怎么量的」写清，后面的数字才站得住）

**取色**：
1. 前景色 = `getComputedStyle(el).color`（占位符取 `getComputedStyle(input, '::placeholder').color`）；若带 alpha（或祖先 `opacity < 1`），按 `fg·a + bg·(1-a)` 先合成到背景上。
2. 背景色 = **CSS 链路合成**：从文本元素往外走，逐层收集 `backgroundColor`，碰到第一层 `a = 1` 停下，再把内层半透明按 `over()` 依次压上去。
3. 链路上只要出现 `background-image`（body 的两层 radial-gradient 就属于这一类），CSS 算不出真值 → **退回截图取样**：`Page.captureScreenshot`（png）→ 自写 zlib/PNG 解码 → 在元素**父盒**内取「出现次数最多的颜色」当底（避开文字笔画色，色差 <90 的像素剔除），记为 `src=px`。本轮 1960 条里 1239 条走 CSS、721 条走像素。
4. 对比度公式（WCAG 2.x）：`L = 0.2126·R' + 0.7152·G' + 0.0722·B'`，其中 `C' = C/255 ≤ 0.03928 ? C/12.92 : ((C/255+0.055)/1.055)^2.4`；`ratio = (L_亮 + 0.05) / (L_暗 + 0.05)`。

**门槛**（本任务给的口径）：正文与次要文字 ≥ **4.5:1**；占位符与 9–11px 角标 ≥ **3:1**；非文本（焦点环 / 图标 / 边框）≥ **3:1**（WCAG 1.4.11 / 2.4.11）。

**角色分类**（自动分，不靠肉眼）：`placeholder` → 占位符；`button` → 落在 `button/a[role=button]/[role=tab]/summary` 里的文字；`micro` → ≤11px；`secondary` → 11–13.5px；`body` → >13.5px。`disabled` 控件单独剔除（WCAG 豁免非活动控件）。

**取样量**：11 屏 × 4 个滚动位（`main._screen` 的 0/⅓/⅔/底）× 每屏 3 个视口 → dev **1960 条**文本样本、dist **1963 条**；作战屏/编队面板另跑，**608 条**（剔除被 72% 遮罩压住的 370 条后，可见 **238 条**）。

## 五、动画与动效（`prefers-reduced-motion: reduce`）

### A11Y3-09 开场 PV 在「减少动效」下照样自动播放（CSS 管不到 `<video>`）
- 严重度：**P2**
- 视图：开场 PV（`components/PvScreen.tsx`，`public/pv.mp4`）
- 复现：`Emulation.setEmulatedMedia({features:[{name:'prefers-reduced-motion',value:'reduce'}]})` → 清 `zts-pv-seen` → 重新加载。
- 实测：`{paused:false, muted:true, currentTime:1.35}` —— 进站即播，`currentTime` 还在往前走；此时页面上 21 条 CSS 动画全部被压成 0.01ms（`_bootSweep` / `_chipIn` / `_pvCardIn` / `_pvSplit` / `_pvWipe` / `_subIn` / `_ornIn` / `_ornSpin` / `riseIn`…），**唯独视频这一层还在整屏位移**。跳过键 `[data-pv-skip]` 在，但那是要用户手动按的。
- 期望：`reduce` 下不放（或改成「静态海报 + 播放键」）；这也是 `PvScreen.module.css:136` 那条 reduced 规则**做不到**的部分（它只管 CSS）。
- 证据：`%TEMP%\a11y3\dev-motion\motion.log` 第 2 行 `PV video with reduce = {"paused":false,...}`、截图 `%TEMP%\a11y3\dev-motion\dev-pv.png`
- 修复建议：`src/lib/pv.ts` 里把「要不要放」多一道 `matchMedia('(prefers-reduced-motion: reduce)').matches` → 直接按「看过」处理（或渲染海报层 + 播放键），别只靠 CSS。

### A11Y3-10 全局 reduced-motion 只压 `duration`，无限动画变成「0.01ms 无限循环」—— 位移归零了，主线程没归零
- 严重度：**P3**
- 视图：全站（`tokens.css:759` 那条 `*{animation-duration:.01ms!important}`）
- 实测：reduce 下仍在跑 4 条 `pulseGlow`（`iterations: Infinity`、`duration: 0.01ms`）；用 CDP `Performance.getMetrics` 量同一屏 2s 的主线程 `TaskDuration`：**reduce 态 45ms / 关掉 `animation` 后 12ms**（`RecalcStyle` 6ms vs 0ms）—— 也就是说「压到 0.01ms」让它一直在重算 `box-shadow`，比彻底停掉贵 **3.75 倍**。
  位移方面是干净的：每次采样 `bigMove = 0`（PV 层 21 条、标题菜单 1 条、外壳 2–3 条、各屏转场 2–9 条），所有 transform 动画在 320ms 内位移 ≤6px。
- 期望：`reduce` 下无限动画应当 `animation: none`（或 `iteration-count: 1`），而不是无限快跑。
- 证据：`%TEMP%\a11y3\dev-motion\motion.json` / `motion.log`（每条动画的 `dur/delay/iter/props` 都在里面）、`%TEMP%\a11y3\cpu.json`（A/B/C 三段读数）
- 修复建议：`tokens.css:759` 里补一行 `*, *::before, *::after { animation-iteration-count: 1 !important; }`（或对 `pulseGlow` / `blink` 这类无限动画单独 `animation: none !important`）。

## 未量 / 未覆盖（别当成「没问题」）

- **390 档的 ARIA 只量了智库首屏**（`missing = 0`）——世界书的行内按钮在首屏之外，这一档等于**未量全**。
- **浮层态未量对比度**：存读档浮层、军需处、作战屏技能/道具/装备展开面板、约会专线右栏（`IntimateHud`）都只在 1440×900 的关闭态下扫过。
- **作战屏的敌方意图/减益标签**只覆盖到入场那一屏（第 1 回合），多回合后的 `data-buff` 标签对比度未量。
- **打字机**：代码里没有逐字打印（推演是流式整段替换），故「打字机动效」这一项**无对象可量**，不是漏掉。
- **暗色 / 高对比模式**：本仓没有这两套主题，未量。
- **截图法本身的局限**：`src=px` 的 676 条里，若元素所在底是渐变（body 那两层 radial-gradient），取的是**采样点**的颜色；同一元素在屏上不同位置的实际对比度可能相差 ±0.3（已用「父盒众数 + 剔除文字色」降低影响）。
