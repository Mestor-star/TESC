### BUG2-01 手机档作战屏：技能 / 道具 / 装备列表被压成 20px 高，一行都看不全
- 严重度：P1
- 环境：dev（`npm run dev` 5174）
- 复现步骤：
  1) 390×844（CDP mobile + 触屏）进站，种一档有进度的运行档，走「任务简报 → 接取 → 出击 → 编队 → 出击」进作战屏。
  2) 方向键把光标走到「技能」，按 Z 打开技能表。
  3) 量 `[data-skill-list]` 的 `getBoundingClientRect().height` / `clientHeight` / `scrollHeight` / `overflowY`，再量每行高度与「完整落在容器内」的行数。
- 实际：`{h:20, clientHeight:20, scrollHeight:220, overflowY:"auto", rowHeights:[142,74], visibleRows:0}` —— 列表只剩一条 20px 的滚动缝，两行技能（142 / 74 高）一行都装不下；同一场仗在 1440×900 上同一个节点是 `clientHeight=186`（正常）。
  截图上「技能」标题下面只剩一道被裁掉的字头，紧接着就是「小队」那一栏。
  ｜期望：手机档也至少能看见一行半（`min-height` 兜底），或把技能表改成整屏浮层。
- 证据：
  - `%TEMP%\bug2-battle3-390\K3-skill-list.png`（技能表只剩一条缝）、`%TEMP%\bug2-deep\X3-skill-390.png`
  - `%TEMP%\bug2-deep\deep.log`「X3 技能面板三层高度 = {console:h240, cmd:h240, sub:h50, list:h20/ch20/sh220}」（console 只分到 240px 的 max-height，cmd 与 sub 逐级把列表压到 20）
  - 对照 `%TEMP%\bug2-battle3-1440\battle3.log`「K2 技能列表 {box:[45,665,714,186]}」（桌面正常）
- 疑似根因：`src/views/Battle.module.css:3103` `.console{max-height:min(240px,29vh)}`（≤640 档）+ `:1612` `.cmd{min-height:0}` 与 `:946/:966/:1247` 一串 `min-height:0` 让 flex 一路收缩，而 `:1391` `.list{max-height:186px;overflow-y:auto}` 只封了上限、没有下限 —— 逐级二分未做，故定为「疑似」。
- 修复建议：给 `.list`（或 ≤640 档的 `.cmd`）补 `min-height: max(2.2 行, 96px)`，或手机档把技能表做成整屏浮层。

### BUG2-02 备份面板：文件选择器一取消，两枚按钮永久灰掉（「读取中…」），只能切视图自救
- 严重度：P1
- 环境：dev（`src/lib/backup.ts` 与线上同一份）
- 复现步骤：
  1) 1440×900 进「终端设置」，滚到「备份与恢复」。
  2) 点「从备份恢复」，弹系统文件框；**按取消**（CDP 侧用 `Page.setInterceptFileChooserDialog` 拦住后，对同一个 input 派发 Chrome 真会发的 `cancel` 事件，等价于用户点取消）。
  3) 看两枚按钮的文案与 `disabled`。
- 实际：`{"pick":{"t":"读取中…","d":true},"exp":{"t":"导出整份备份","d":true}}` —— 「从备份恢复」永远停在「读取中…」，**连「导出整份备份」也一起变灰**；再点没反应（disabled），页面上没有任何说明。切到别的视图再回来才恢复。
  ｜期望：取消 = 什么都没发生（按钮复原、无报错）；或读超时给一句「没有选中文件」。
- 证据：
  - `%TEMP%\bug2-backup4\backup4.log`「C 取消后 = …读取中… d:true…」「C 再点一次 chooser=false …d:true…」「C 二次选择后 = …d:true…」
  - 截图 `%TEMP%\bug2-backup4\C-after-cancel.png`、`C-after-second.png`
  - 同一条路的另一半：只要 `input.click()` 因故没弹出（非用户手势被浏览器拒绝），也是同一个死状态 —— `%TEMP%\bug2-backup2\backup2.log`「D4 bad-magic… pickTxt 读取中… d:true」+ 控制台 `File chooser dialog can only be shown with a user activation`
- 疑似根因：`src/lib/backup.ts:491-513` `pickBackupFile()` 只手挂了 `onchange`，没有 `cancel` 监听、也没有超时；Promise 永不 settle → `src/views/Settings.tsx:369-388` `doPick()` 的 `finally{setBusy(null)}` 永不执行。
- 修复建议：给 input 补 `addEventListener('cancel', () => resolve(null))`（Chrome 113+ 会发），并在 `doPick` 外层加 60s 超时兜底。

### BUG2-04 作战屏全屏浮层不困住焦点：Tab 12–13 步就跑到屏外导航
- 严重度：P2
- 环境：dev，1440×900 与 390×844 都有
- 复现步骤：进作战屏 → 连按 Tab，记录 `document.activeElement`；到屏外那一枚按钮时按 Enter，看视图与作战屏。
- 实际：Tab 顺序 `撤出 → 敌卡 → 信息 → 角色介绍 → 连携条件表 → 战报行 → 关闭 → 小队 → BODY → 终端总览[nav]…`，第 12 步（1440）/ 第 13 步（390）落在屏外导航「终端总览」上 —— 它被作战屏整块盖着，读屏软件仍会读出来；此时按 Enter 不生效（被作战屏的 keydown 以 preventDefault 吞掉），方向键仍在动作战屏光标。等于键盘用户摸到一片「看得见读得到、点了没反应」的幽灵焦点。
  ｜期望：全屏浮层期间把底下外壳设成 `inert`（或给 root 加焦点环），Tab 只在作战屏内部循环。
- 证据：`%TEMP%\bug2-battle-1440\battle.log`「B7 Tab 12 步: …button._navItem_1kx58_133 [OUT]:终端总览…」；`%TEMP%\bug2-final\final.log`「G3 Tab 逃逸 = {step:13, txt:终端总览}」「G4 Enter 前后 = {h1 都是「任务简报板」, battle:true}」；`%TEMP%\bug2-escape\E1-focus-out.png`
- 疑似根因：`src/views/Battle.tsx:1094-1099` 用 `createPortal` 挂到 body，只设了 `tabIndex={-1}` 与自动 focus（:861），没有 `inert` / 焦点环；`App.tsx` 的外壳在浮层期间照旧可聚焦。
- 修复建议：作战屏挂载时给 `.app--stage` 加 `inert`，卸载时摘掉。
