# 叙事自由度改造方案

> 目标：主人要的是「剧情不要太固定，要更自由」，但**大事件还是会发生**。
> 本文件只做诊断与方案，不改任何产品代码。
> 结论一句话：**提示词这一层已经很自由了，真正替玩家做决定的是「结构」—— 唯一的推进指针、只听模型 `eventDone` 的收束、被事件钉死的地点与在场名册、以及没有任何后果的 `diverged`。**

---

## 0 · 审计结论速览

| 层 | 现状 | 谁在做决定 |
| --- | --- | --- |
| 导演提示词（`src/lib/plot.ts`） | 已明确「大纲只是参照系／七比三／他写下的就是已发生」 | 玩家（已经比较自由） |
| 推进结构（`src/views/Plot.tsx` + `src/terminal/Terminal.tsx`） | 唯一焦点段、只认模型 `eventDone`、门禁硬拦 | **系统** |
| 世界状态（`src/data/types.ts`） | 地点/名册由事件静态数据 + 模型指令决定 | **系统 / 模型** |
| 偏离记录 | `diverged` 只上屏 + 进记录，无任何后果 | **无人** |

所以改造的重心不在「再写一段更自由的提示词」，而在**拆掉 4 个结构锁**（D1/D2/D6/D8）与**补 2 个缺失机制**（D3 时间、D4 锚点/D5 后果）。

## 1 · 现状清单（带证据）

### P1 · 推进指针唯一：玩家不能选段、不能跳段、不能并行
- `src/views/Plot.tsx:704` 　`const focusEv = useMemo(() => EPISODES.find((e) => !epDone[e.id]) ?? null, [epDone])`
- 全终端只有这一个「当前段」：右栏事件卡（`Plot.tsx:1695`）、提示词上下文（`Plot.tsx:1047-1114`）、会话日志（`Plot.tsx:716`）、离线正文（`Plot.tsx:1596`）都跟着它。
- 玩家的实际能力：**只能推账上第一个没收束的那一格**。想先去看别的事、想中途退回几段、想同时开两条线，都没有入口（`EPISODES` 是线性读序，见 `src/lib/freetime.ts:92-119`）。
- 连带影响：情景记忆库的「进行中」也写死在这一段（`src/lib/memory.ts:156-158`），角色主动来信只算这一段在场的人（`src/lib/smsauto.ts:107-108`）。

### P2 · 收束只有一条路：模型回 `eventDone`
- `src/views/Plot.tsx:914-928`：只有指令里的 `fx.eventDone` 才 `applyConcluded(...)`，收束栏「进入下一事件」（`Plot.tsx:2385-2408`）才会出现。
- `Plot.tsx:1412-1441` `advanceFromConcluded`：玩家点的那一枚只是「把模型已经宣布的收束写进记录」——**玩家没有说「这段我到此为止」的权力**。
- 指令 schema 里收束只有这一格：`src/lib/plot.ts:1877` `"eventDone": true`。
- 对照：**唯一一处玩家说了算的收束**是卷间自由段（`Plot.tsx:1453-1460` `endFree` + `Plot.tsx:1955-1966` 「进入下一卷」），道理写在 `src/lib/freetime.ts:149-162` `FREE_FRAME`（「什么时候收由操作员说了算」）。这正是可以推广的样板。

### P3 · 离线通读同样被困
- `Plot.tsx:1596-1602`：离线收束也是「整篇读完 → `completeEvent`」，中途没有「先放着／走开」的出口；且它同样吃门禁（`Terminal.tsx:1448`）。
- 玩家实际能做的：读完全文或什么都不做，二选一。

### P4 · 门禁（bond gate）是硬拦，且机制替玩家定价
- 计算：`Terminal.tsx:1038-1045` `gateMissing`；文案：`Terminal.tsx:1048-1052` `gateText`。
- 三处硬拦：
  - 阅读推进 `Terminal.tsx:1371-1379`（`markRead` 直接 return）；
  - 收束 `Terminal.tsx:1448`（`completeEvent` 返回 false）；
  - 界面 `Plot.tsx:1423-1427`（「这一段还收不了」）。
- 语义来源 `src/data/types.ts:296-305`：`gate` = 「好感得先到某个数，这一段才开得了」。
- **数据现状：`src/data/timeline.ts` 里 `gate:` 0 处**（`unlock: true` 在 :44，`lock: [{char:'luna',value:100}]` 在 :115）。也就是说这套「替玩家决定关系必须走到哪儿」的机器今天还没上膛，但通路已经装好了 —— 一旦填数据，玩家就得先把某段关系刷到某个数才准往前，这正是要拆的东西。

### P5 · 地点被事件钉死：玩家不能离开这里
- `src/lib/plot.ts:1831-1833`：【当前事件】${ev.group} · ${ev.phase}｜${ev.place} 直接念事件静态地点。
- 指令 schema 里**没有 place**（`plot.ts:1864-1909` 全部字段），`world.cast` 只有在场名单（`types.ts:759-767`）。
- 玩家实际能力：他写「我走了／我们去别处」，只能指望导演自己在正文里换场，系统侧的「此刻在哪」不会变 —— 下一回合的地点行照旧。

### P6 · 在场者默认被 cast 锁死，且「全走光」表达不出来
- 静态回落：`Terminal.tsx:1155-1158` `castOfEvent` → `world.cast?.[ev.id] ?? castOf(ev)`；提示词侧 `plot.ts:1615-1620` `presentOf`。
- 唯一改写口：模型指令 `cast`（`plot.ts:1874`，落地在 `Plot.tsx:846-850`）。
- **空名单写不进去**：`Terminal.tsx:1164-1167` `if (!ids.length) return` —— 于是「他把人全赶走了／这一场散了」在数据上无法表达，下一回合人又全回来了。
- 玩家实际能力：说出「你走开」之后，是否真的走了，取决于模型这一回合给不给 `cast`。

### P7 · 没有时间轮子：不能说「我等三天」
- `TimelineEvent.day` 只是字符串时间标（`types.ts:276`）；`WorldState`（`types.ts:725-812`）里没有时钟、没有 tick、没有「过了几天」。
- 玩家实际能力：写「三天后」只能靠正文叙述，系统侧一切（在场、地点、锚点、门禁）都不动。
- 这条直接决定了 P2：**没有时间轴，就没有「时间到了自动收束／自动触发」的第二条路**。

### P8 · `diverged` 只被记账，没有任何后果
- 写入：`Terminal.tsx:1459` `WorldRecord.diverged`（指令解析 `plot.ts:530-531`、`plot.ts:1146-1148`）。
- 消费方**全部是展示**：
  - `Plot.tsx:930-932` 一条 toast「路线偏离」；
  - `Plot.tsx:2405` 收束栏前缀「分歧路线 · 」；
  - `src/views/Saga.tsx:52`、`:265` 分歧计数与标记；
  - `src/lib/memory.ts:111`、`:132`、`:320`、`:357` 事迹里的标记位。
- 也就是说：**玩家把原著整段推翻，世界下一段照旧**。没有代价、没有补偿、没有「本来会发生的事换个方式回来」。`BRIDGE_ON_ADVANCE` 默认还是 `false`（`Plot.tsx:124`），连衔接开场都不发。

### P9 · 后接事件「软门禁」把玩家的收束方向往下一段拽
- `src/lib/plot.ts:1419-1428` `nextAnchorBlock`：`plot.ts:1427` 要求「**能把当下局面自然引向后接事件的入口**」才准 `eventDone`。
- `plot.ts:1392` 同一条：「且收束叙述与后接事件的开端自然衔接时」。
- 有退路（「收不上就不要收」），但它是「玩家为什么总被拽回原文」的第一因：不往那儿收，就不许收。

### P10 · 不能拒绝、不能推迟、不能跳过某个事件
- `nextEpisodeAfter`（`src/lib/freetime.ts:133-140`）只认 `epDone` 的布尔，没有任何「推迟到下一格」的状态。
- 回退只有一格：`Plot.tsx:1782-1797` 只撤**最近收束的那一段**（`reopenEvent`，`Terminal.tsx:1477-1525`）。
- 没有「暂不参与／绕开」的表达。

### P11 · 世界知识按进度上闸（防止提前知道，但也限制自由探索）
- `src/lib/lorescan.ts:25-36` `allowGateFor`：世界书条目只在「该段已收束或正是当前焦点」时放行；短信侧更严（`:40-51` 只放已收束）。
- 这是**正当收束**，但和 P1 叠起来就成了：玩家既不能去，也不能读。

### P12 · 引导文案把线性当规则讲给玩家
- `src/lib/guide.ts:300`「剧情推进——记录在这里复盘，**一次推一格**。」
- `guide.ts:308`「已收束的格子左边打记号，能翻回去看，**不能改**。」
- `guide.ts:226-227`「顺序是：终端总览 → 剧情推进 → 收束后回终端总览看数。」
- 这是软约束（纯文案），但它塑造玩家预期：让人以为「越过这一段」是非法的。

### P13 · 交战未了硬卡推进（这条是对的，别动）
- `Plot.tsx:1417-1420`：本段有 `pendingBattle` 就推不动。结算一致性要求如此。
- 同类窄闸 `Plot.tsx:899-901` `eventHasNoFoe`：原文没对手的段丢弃交战指令（防幻觉）。也保留。

### P14 · 事件结构里根本没有「必须发生」的位置
- `TimelineEvent`（`types.ts:266-308`）字段只有 `summary / entities / chars / cast / bond / gate / lock / script / unlock`。
- 「必须发生」今天全靠提示词一句 `plot.ts:1388`「不得替模型自行了结大纲尚未交代的悬念」撑着 —— **没有数据载体，也就无法校验、无法让别的支线对接**。这是「大事件锚点」支线要填的坑。

### 现状能力矩阵（玩家到底能做什么）

| 玩家想做的事 | 能做吗 | 卡在哪 |
| --- | --- | --- |
| 中途离开当前事件（换个地点） | ✗ | P5（地点无字段）、P6（名册只有模型能改） |
| 拒绝参与某个事件 | ✗ | P10（无「绕开」状态） |
| 让本该发生的事不发生 | 一半 | 提示词允许（`plot.ts:1386`），但系统不记录「它没发生」 |
| 让本该发生的事推迟 | ✗ | P7（无时间） |
| 自己宣布这一段结束 | ✗ | P2（只有自由段有 `endFree`） |
| 换一个人在场 | ✗（间接） | P6（靠模型给 `cast`；且「全走光」写不进） |
| 越过当前事件去别的段 | ✗ | P1（唯一 focus） |
| 做与原文相反的选择 | ✓ | `plot.ts:1386`、`1481-1500` `willSection`（七比三）—— 但后果为零（P8） |
| 完全不按大纲过一段日子 | ✓ | `Plot.tsx:1935-1953` 自由活动开关 + `freetime.ts:149-174` |

## 2 · 改造原则（三档）

### A 类 · 必须发生（大事件锚点）
- **结果不可跳过**：锚点规定的「世界状态变化」一定落地（某组织成立、某人失去什么、某场灾难发生）。
- **过程 / 代价 / 关系 / 见证人可变**：谁在场、以什么形式、付出什么、玩家站在哪一边，都由玩家。
- 判定标准（写进数据）：锚点只有 `outcome`（一句结果）与 `variable`（可变量清单），**不写过程**。

### B 类 · 可以推迟或换形式
- 玩家绕开时，事件**换个入口回来**：换地点（追到他面前）、换发起人（换个人来提）、换代价（多付一笔）、换时机（晚两格时间）。
- 数据上线：`fallback`（替代形态）与 `when.minTick`（最晚何时必须到）。

### C 类 · 完全自由
- 日常、私聊、约会、探索、办事、发呆：不写进 `epDone`、不动主线指针、不触发锚点。
- 样板已经在跑：自由活动开关 + 卷间自由段（`freetime.ts:149-174`），羁绊在落地层冻结（`Plot.tsx:818-822` `freezeBond`）。

## 3 · 具体改造方案（按「改动量 / 风险 / 收益」排序）

> 每条都写明：改哪个文件 / 加什么结构 / 提示词改哪一句 / 存档影响 / 怎么验证。

### D1 · 收束加一条「玩家说了算」的通道 ★改动量小 · 风险低 · 收益最高
- **改哪**：`src/views/Plot.tsx`（收束栏 `2385-2408` 加第二枚按钮）、`src/data/types.ts:444`（`RecordMode` 加 `'manual'`）、`Plot.tsx:187` `MODE_LABEL` 与 `src/views/Saga.tsx:17` `REC_MODE_LABEL` 各补一行。
- **加什么**：按钮 `data-conclude-manual={ev.id}`，文案「这一段落幕（我判定）」。点下去走既有 `completeEvent(ev.id, digest, 'manual', diverged)`：`digest` 取 `ev.summary + '（由操作员判定落幕）'`，或取本段最近几条正文的首句拼一句。**不新增 state**（`epDone` 已有），只新增一枚按钮。
- **提示词**：不动。（`eventDone` 仍是「自然收束」的首选路，人工是兜底。）
- **存档影响**：`RecordMode` 加一个枚举值，旧档不会有它；`src/lib/slots.ts` 全文没有对 `mode` 做白名单校验（已核），旧档读入无风险。`tsc` 会强制补两处 `Record<RecordMode,string>`。
- **验证**：`npm run lint` → `npm run build`（两处 `Record` 缺项会当场报错）；冒烟新增一条：自由段之外也能出现该把手、点一下后 `[data-records]` 计数 +1、`[data-focus-ev]` 前移。既有断言点 `data-concluded`（`scripts/smoke/smoke.mjs:163`、`:689`）不受影响。

### D2 · 焦点可选：从「唯一焦点」到「已在手边的那几格可切」 ★改动量中 · 风险中 · 收益高
- **改哪**：`src/views/Plot.tsx:704`、`src/terminal/Terminal.tsx`（新增 state + 落盘，紧邻 `epDone`）、`src/lib/slots.ts`（可选字段登记）、右栏（`Plot.tsx:1929-1980` 那一排）。
- **加什么**：
  - `WorldState.focusEvId?: string`（可选，旧档缺省 = 现行为）。
  - `focusEv = EPISODES.find(e => e.id === world.focusEvId) ?? EPISODES.find(e => !epDone[e.id]) ?? null`。
  - 右栏加一枚「换一段」下拉，候选集**只含**：① 第一个未收束段；② 紧随其后的那一格卷间自由段；③ 已收束段的回看（只读正文，不推演）。不做「任意跳段」—— 见第 4 节。
- **提示词**：不动（`buildDirectorSystem` 只吃传进来的 `ev`）。
- **存档影响**：新增可选字段，只读可省；`hydrateWorld` 照既有惯例给默认值即可。旧档不迁移。
- **验证**：读档后焦点落回存档里那一段；冒烟加一条「切到自由段 → 再切回 → `data-focus-ev` 不变」。

### D3 · 时间格：给世界一个能走的钟 ★改动量中 · 风险中 · 收益高（也是锚点的地基）
- **改哪**：`src/data/types.ts`（`WorldState` 加 `tick?: number`，与 `free`（`:812`）并列）、`src/terminal/Terminal.tsx`（`tickOnce()` / `advanceTick(n)`）、`src/views/Plot.tsx`（右栏加「过一段」（+1）与「过一宿」（+4）两枚，`data-tick` 把手）、`src/lib/plot.ts:1831`（【当前事件】多一行）。
- **加什么**：
  - `tick` 单调递增整数，**不进记录、不参与任何数值结算**（第一版纯叙述锚）。
  - 每次推演回合一并 `+1`（现在没有回合计数，顺手有了）。
  - 玩家按钮 `+n` 时同步 `push('info','时间推进', ...)`，并让下一回合提示词带上「距上一幕已过 N 格」。
- **提示词一句话**（插在【当前事件】块里）：「【此刻】这一段是第 ${tick} 格时间；他若说『过了三天』，就按过了三格写 —— 世界自己也在动，别把时间冻住。」
- **存档影响**：`tick` 可选，缺省 `0`；`slots.ts` 登记为可选。**不要**把它塞进 `epDone`/`cur`（那两个是阅读进度）。
- **验证**：冒烟：点 `[data-tick]` → `localStorage['zts-terminal:v3']` 里 `tick` +1；读档后仍是那个值。

### D4 · 锚点机制：必须发生的那件事有地方登记 ★改动量中大 · 风险中 · 收益最高（**需与考据支线合并**）
- **改哪**：新增 `src/data/anchors.ts`；`src/data/types.ts` 加 `Anchor` / `AnchorWhen` 与 `WorldState.anchors`；`src/lib/plot.ts` `buildDirectorSystem` 加【锚点】节；`src/views/Plot.tsx` 每回合末算 `dueAnchors` 上屏并给指令落地。
- **加什么结构**（对接契约见第 6 节）：

```ts
// src/data/anchors.ts
export interface AnchorWhen {
  afterDone?: string[]   // 这些段都收束后「才可能」到来
  minTick?: number       // 时间格到这儿就「必然」到来（依赖 D3）
  place?: string         // 此刻在此地
  cast?: string[]        // 这些人里至少一人在场
  flag?: Record<string, boolean | number | string>
  playerAct?: boolean    // 玩家主动踩上去（去了那个地方／问了那句话）
}
export interface Anchor {
  id: string             // 'anc-v1-05-contract' —— 稳定 id，考据支线回填
  evId: string | null    // 挂靠的原文段（跨段锚为 null）
  title: string
  when: AnchorWhen       // 任一条件组满足即算「到来」；minTick 是硬期限
  outcome: string        // 结果句（不可跳过的那部分），只写世界状态变化
  variable: ('form' | 'cost' | 'relation' | 'who' | 'when')[]  // 可变量
  fallback?: string      // 玩家绕开时的替代形态（B 类回收）
  guard?: string         // 未到时给导演的禁令（一句话）
}
```

- **落地三处**：
  1. **提示词**（`plot.ts` 在【事件大纲】之后插一节）：
     - 未到：「【锚点 · 还没到】${guard}。这些事现在不许写掉，也不许提前给出结果。」
     - 到期：「【锚点 · 已到期，必须落地】${outcome} —— 过程、代价、在场的人、他站在哪一边，全由他这一回合的写法定；但结果必须发生。」
  2. **触发**：`Plot.tsx` 每回合结束后用纯函数 `dueAnchors(world, tick)` 现算 `due`，写进 `WorldState.anchors[id] = { at: tick, evId, form?: string }`，并 `push` 一条提示。
  3. **校验（防「世界失焦」）**：`minTick` 到期的锚点若连续 3 回合还没落地，**在本地把它的 `outcome` 直接写进下一回合提示词的最末**（压过一切），不再等模型配合。
- **存档影响**：`WorldState.anchors?: Record<string, { at: number; evId: string | null; form?: string }>`，可选；旧档 = 空表（= 「所有锚点都还没到」，正是旧档该有的语义）。
- **验证**：纯函数 `dueAnchors` 单独验证（脚本直算即可）；冒烟加一条：把 `tick` 顶到某锚点的 `minTick`，断言提示词（或 UI 横幅）里出现 `outcome` 的子串。

## 6 · 与「大事件锚点」考据支线的对接契约

> 那支在考据原文，产出的是「哪些事必须发生」。本方案需要的字段如下 —— **只填这些，过程一个字都不要**。

| 字段 | 类型 | 谁填 | 说明 |
| --- | --- | --- | --- |
| `id` | `string` | 考据支线 | 稳定 id，建议 `anc-<卷>-<序号>-<短名>`，如 `anc-v1-05-contract`。**跨版本不变**，存档靠它。 |
| `sourceRef` | `{ vol: number; ch: string }` | 考据支线 | 原文出处（卷/话），只作考据，不进提示词。 |
| `evId` | `string \| null` | 考据支线 | 挂靠的 `TimelineEvent.id`（如 `'v1-05'`）；跨段/卷间锚填 `null`。 |
| `title` | `string` | 考据支线 | 一句人类可读的名字（上屏用）。 |
| `outcome` | `string` | 考据支线 | **不可跳过的那一句结果**（只写世界状态变化，不写过程、不写谁说了什么）。 |
| `variable` | `string[]` | 考据支线 | 可变量，取值域 `form / cost / relation / who / when`（过程形状 / 代价 / 关系 / 见证人 / 时机）。 |
| `when` | `AnchorWhen` | 设计侧先给默认值 | 触发条件组：`afterDone / minTick / place / cast / flag / playerAct`。**`minTick` 是硬期限**（到点必达）。 |
| `fallback` | `string?` | 考据支线 | 玩家绕开时的替代形态（B 类回收）。例：「他没去赴约 → 对方亲自找上门」。 |
| `guard` | `string?` | 考据支线 | 未到时给导演的一句禁令。例：「契约还没签，别让委员会提前认他当使用者」。 |
| `span` | `{ min: number; max: number }?` | 考据支线 | 这一段原文的时间跨度格数（配合 D3 的 `minTick` 与收束判定）。 |

**给考据支线的三条硬要求**
1. `outcome` 必须是**状态句**（谁—变成—什么），不能是**过程句**（「两人打了一场」）。过程由导演写，玩家可以改写。
2. 每个锚点必须能回答：「玩家绕开它时，它怎么回来？」—— 答不上来就不要登记为锚点，降级为 C 类（完全自由）。
3. `id` 一旦进存档就不能改；改 `outcome` 文案可以（那只是提示词）。

**与现有数据的连接方式**：不改 `TimelineEvent` 结构 —— 用 `tid = ev.id` 反查即可（`ANCHORS.filter(a => a.evId === ev.id)`），同一段可以有 0~n 个锚点。

## 8 · 一句话总结

**提示词已经让位给玩家了，是结构没让位。**
先给玩家「走开、收工、耗时间」这三个动作（D6/D1/D7），再补时间与后果（D3/D5），最后把「必须发生」从提示词搬进数据（D4）—— 那时「大事件还是会发生」才第一次成为**可校验的事实**，而不是模型今天心情好才照办的一句话。
