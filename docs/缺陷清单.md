### BUG-01 读档 / 重置世界不清存档之外的运行态（约会名册 · 短信线程表 · 未读计数），造成串档
- 严重度：P1
- 环境：两者皆是（逻辑在 src/lib/slots.ts，线上本地同一份；本轮证据取自本地 dev）
- 复现步骤：
  1) dev 起站（npm run dev，5174），让运行档有进度；预置「上一档遗留的运行态」：zts-rendezvous:v1（一条未散场的 Rendezvous）、zts-sms-threads:v1（一条自建群）、zts-sms-unread:v1（{hikari:3}）。
  2) 页面内调 import('/src/lib/slots.ts')：captureSnapshot({...}) → writeSlot(0,...) → applySnapshot(readSlot(0).snapshot)。
  3) 对照读档前后这几个键。
- 实际：zts-plot-pending:v1 被正确清掉、cur 正确换成本档的 v1-1；但 zts-rendezvous:v1、zts-sms-threads:v1、zts-sms-unread:v1 **原样残留**（读档后仍是上一档的内容）。
  ｜期望：读档 = 整轮运行态换成本档，存档之外的那三样要么进快照、要么同 clearRunStorage 一样清掉。
- 证据：
  - %TEMP%\bugshot-flow\flow.log 里「A 存档/读档遗留键」：after: {unread:0, rendezvous:"[{id:date-old,cast:hikari,open:true}]", threads:"[{id:grp-old,members:[hikari]}]", pending:null, cur:"v1-1"}
  - %TEMP%\bugshot-state\state.log：预置 zts-sms-unread={hikari:3}、会话账为空 → 侧栏角标读作 "3"，进短信页后该线程写着「本线程还没有消息」，角标也没得清（截图 %TEMP%\bugshot-state\F2-sms-stale-unread.png）。
- 疑似根因：src/lib/slots.ts:196 applySnapshot() 只写回 RUN_KEY / PLOT_KEY / TAVERN_KEY 并 remove PLOT_PENDING_KEY（:226-230），而 clearRunStorage()（:249-259）才连 RENDEZVOUS_KEY 一起清 —— 两条路径口径不一致，正是该文件 :235-248 自己写下的那条规矩（「新增持久化状态必须…在存档读写里登记」）漏了三处：zts-rendezvous:v1（lib/rendezvous.ts:42）、zts-sms-threads:v1（lib/smsthreads.ts:28）、zts-sms-unread:v1（lib/sms.ts:126）。未读那一支还多一层：lib/sms.ts:146 的 let unread = loadUnread() 是模块加载时的快照，读档改写 localStorage 不会回声。
- 修复建议：把这三样登记进 RunSnapshot（与 guide 一样可缺省），applySnapshot 里一并对齐 / 清空；sms.ts 补一个 reloadUnread() 在读档后调用。

### BUG-02 手机上短信输入框落在首屏之外；键盘一弹出就彻底够不着
- 严重度：P1
- 环境：两者皆是（线上与本地实测数值一致）
- 复现步骤：
  1) 390×844（mobile 模拟 + 触屏）打开站点，进入「短信」，点开任一联系人。
  2) 量输入框位置；再把内层滚动容器 .screen 滚到底复量。
  3) 把视口压到 390×420（≈ 手机键盘弹出后的可视区），再复量 + 尝试滚动。
- 实际（本地 dev / 线上各跑一遍，数字几乎相同）：
  - 844 高：输入框 top=923 bottom=962，视口 844 → **首屏看不到**；.screen 内滚到底（468~472px）后降到 top=680 才可见。
  - 420 高：输入框仍在 top=680 bottom=720，.screen 已不再是可滚容器（screen:null），窗口也不可滚 → **怎么滚都够不着，键盘还挡在上面**。
  ｜期望：输入带贴着可视区底边（sticky / 面板内部滚动），键盘弹出时随 visualViewport 上移。
- 证据：%TEMP%\bugshot-sms2.mjs 输出（本地 M1/M2/M3/M4，线上同一份数字）；截图 %TEMP%\bugshot-sms2\M2-scrolled-bottom.png（滚到底才露出输入带）、M4-keyboard-bottom.png（键盘档：完全看不到输入带）、%TEMP%\bugshot-ui\D2-sms-keyboard.png、%TEMP%\bugshot-sms\S1-sms-390.png。
- 疑似根因：src/views/Comms.module.css:169-173 手机档把 .wrap 改成 height:auto + .chatPane{min-height:480px}，输入带（.composer，:155）只是聊天面板末尾的一个普通块，不 sticky；面板总高（contactList 260 + chatPane 480）本就超出 390×844 视口，键盘一压，外层 .screen 收起后内容直接溢出且无处可滚。
- 修复建议：手机档把短信页做成「列表 + 会话」两屏，或让 .wrap 保持 100dvh 型定高、只让消息区内部滚动，输入带固定在面板底。

### BUG-03 未配置通道时点「约会专线」会被整页踢到「终端设置」，且进来就自动发起一轮推演请求
- 严重度：P2

- 复现步骤：
  1) 种一档有进度的运行档（zts-terminal:v3），并在 zts-rendezvous:v1 放一条未散场的 Rendezvous（charId:'hikari'）。
  2) 进「剧情推进」，点页签「约会专线 · 1」。

  ｜期望：车道照常打开（空档时写明「等对方先开口」），把「去配置」做成一条可选入口，不要直接把视图换走；自动开口做成显式的那一枚动作。

- 疑似根因：src/components/DateLane.tsx:404-413（空线程即自动 fireDate）+ :211-215（通道未就绪 → push(warn) + navigate('settings')）。
- 修复建议：把 navigate('settings') 换成气泡里的一个按钮；自动开口前先看通道是否就绪，不就绪就别发起。
